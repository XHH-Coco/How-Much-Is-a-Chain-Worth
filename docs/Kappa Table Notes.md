# κ 表读法（H2 的判据）

> 这张表回答的是**一句话**：训练数据从 300 条涨到 2 万条（两个十进位），**Λ 动了多少**。
> κ = dΛ / dlog₁₀n。κ ≈ 0 = 数据涨了缺口没关，这就是 H2 主张的东西。
>
> 表：`results/aggregate/kappa.csv`（一数据集一行）、`kappa_cells.csv`（一 (数据集, 折, 档位) 一行）。
> 入口：`python scripts/06d_kappa.py`。决策：D-69（链臂用 A3）、D-70（train_one 接口对齐）、
> D-71（重采样形状 + 主表任务边界）、D-72（κ 的 12 条测试）。

## 1. 这 40 条是怎么来的

| 项 | 值 | 出处 |
|:--|:--|:--|
| 任务 | `pb26_scaling_cp`（MD_5000 Cp，机制实验，**不进主表**） | `configs/tasks/pb26_scaling_cp.yaml` v2 |
| 档位 | 交替 300 / 1000 / 3000 / 10000 / `all`(22,242)；均聚 300 / 1000 / `all`(1,440) | 官方 `manifest.json` 的 `train_sizes` + 全池锚点 |
| 折 | 官方 `seed_42` 五折 × 2 个数据集 = 10 折次 | `splits/polybench26/pb26_scaling_cp/` |
| 种子 | **seed 0**（只有一档：A2 那 40 条也只有 seed 0） | `scaling_chain.yaml` 的 `seeds` |
| 臂 | 链臂 = **A3 图臂**（`a3_graph`）；单元臂 = A2（`a2_conventional`，XGBoost） | D-69 |
| 条数 | 8 个(数据集,档位) × 5 折 = **40 条** | `expected_fits: 40` |

**档位是官方的，不是我们挑的。** `create_scaling_splits.py` 的定义就是 `train_pool[:N]`；均聚官方只有
300/1000 两档，缺 3000/10000 是事实（硬凑会让曲线失真）。取法由 `graph.n_level_rows(rule="prefix")`
执行——与 A2 **同一份实现**，所以两支臂在每个档位落在同一批训练行上，凭据是记录里的
`n_subset_sha256`（逐格相同，有测试守门）。

## 2. 四个数怎么算

- **Λ（每个单元格）** = (R²_链 − R²_单元) / (1 − R²_单元)。分母是"单元臂没解释掉的方差"，
  分子是"链信息又收回来的那部分"。
- **κ（每个数据集）** = 先按折求 Λ 对 log₁₀(n_train) 的斜率，再对折取平均。**不是**把所有点堆起来
  做一次 OLS：同一条曲线上的点彼此相关（同一测试集、嵌套训练集），而池化 OLS 的权重是
  Σ(x−x̄)²——**档位跨度大的那一折会单独决定斜率**。实测（`tests/test_kappa.py`）：折 A 的四个档位
  挤在 0.13 个数量级、折 B 的两个档位隔 4 个数量级，池化给 −0.05（几乎就是折 B 自己），按折平均
  给 −0.125。池化值 `kappa_pooled` 只作对照，不进结论。
  实测一个**巧合**要写清楚：本任务的 5 折用**同一套档位**（平衡设计），此时池化斜率在数学上
  **恒等于逐折斜率的算术平均**——`kappa.csv` 里这一列与 `kappa` 逐位相同不是"两法互证"，
  是同一个数。想看出两法的差别，得看 `tests/test_kappa.py` 里那个不平衡的例子。
- **该不该报斜率**（`slope_status`，D-74）：两个门槛都要过——档位跨度 ≥ **0.5** 个数量级，
  且相邻档位最小间隔 ≥ **0.25** 个数量级。不过门槛的写 `no_slope_span` /
  `no_slope_overlapping_tiers`，`kappa` 及其两列留空，`verdict` 写 `no_slope`。
  两端连线斜率另存 `endpoint_slope`——它是斜率，但**不是 κ**，没有不确定度。
  判据不是"档位数 ≥ 3"：均聚 300 / 1000 / 1440 有三档，顶上两点只隔 0.158 dex。
- **区间** = 配对 bootstrap（B=2,000、seed 固定）：同一个测试点在两条臂上的残差一起被抽中，
  而且**该折的所有档位共用同一组下标**——因为官方 scaling 的测试集在各档位逐行相同，这正是
  "曲线形状"能被重采样的前提。实现上逐档位取 `(B, n)`：把各档位堆成 `(p, n)` 再用二维下标去取，
  得到的是 `(p, B, n)` 三维数组，值是正确的、但形状会让 `_lambda_rows` 的 `ij,ij->i` 直接报错
  （D-71）。
- **杠杆检查**（`kappa_leverage.csv`，D-3 验收标准 ②）= 去掉 n 最小的一档重拟合，报 κ 是否**翻号**。
  判据只看符号：幅度一定会变（最小档的分母最大、Λ 最不稳），"变了"不是发现，"翻号"才是。
  若删档后不再满足上面的门槛，就写"无法比较"，不硬给一个数。

## 3. H2 的两个条件，分开报

提案 §H2 的判据是两个条件**同时**成立才算被推翻：

1. κ 的 95% 区间**整段 < 0**（数据涨了 Λ 确实在降）；
2. **最大档位的 Λ 掉到最小档位的一半以下**（降幅够大，不是"统计上显著但微不足道"）。

`kappa.csv` 用 `h2_sign_negative` / `h2_lambda_halved` / `verdict` 三列分开写，`verdict` 只会是
`H2_not_refuted` / `kappa_negative_but_lambda_not_halved` / `H2_refuted` 之一。

**"一半"只在 Λ_first > 0 时有意义。** Λ 是比值，分子为负时它是负数，"一半"对负数没有定义。
这种情况下 `lambda_ratio` 写 `undefined` 而不是硬算一个数——把负比值写进报告，比不写更误导。

## 4. 实测（2026-11-17，40 条链臂落地后）

| 数据集 | κ | 95% 区间 | Λ：300 档 → 最大档 | 减半比 | `verdict` |
|:--|--:|:--|:--|--:|:--|
| `md5000_alternating_cp` | **−0.0863** | [−0.1053, −0.0672] | +0.2946 → +0.1915 | 0.650 | `kappa_negative_but_lambda_not_halved` |
| `md5000_homopolymer_cp` | **不报**（`no_slope_overlapping_tiers`） | — | +0.0415 → +0.4824 | 11.620 | `no_slope` |

逐折斜率（交替集）：−0.107 / −0.100 / −0.061 / −0.063 / −0.101，五折同号——**没有一个折在往上走**。

均聚集**不报 κ**（D-3 验收标准 ④）：它名义上有 3 档，但 `1000 → 1440` 只隔 **0.158 个数量级**，
实质仍是两点连线。此前那一版报过 +0.6949 [+0.1876, +1.3605]，那是被**同一折**（斜率 2.075）拉起来的：
逐折斜率 +0.471 / **+2.075** / +0.532 / +0.269 / +0.127，一个折贡献了均值的一半。两点连线斜率
（`endpoint_slope`，无不确定度、只作参考）为 +0.647。

**逐档 Λ 的形状是驼峰，不是直线**（交替集，5 折均值）：

| 档位 | 300 | 1,000 | 3,000 | 10,000 | all (22,242) |
|:--|--:|--:|--:|--:|--:|
| Λ 均值 | +0.2946 | **+0.5029** | +0.3675 | +0.2785 | +0.1915 |
| `1 − R²_unit` 中位 | 0.1280 | 0.0721 | 0.0496 | 0.0392 | 0.0341 |
| `unstable` 格数 | 0/5 | 0/5 | **3/5** | 5/5 | 5/5 |

所以一条直线的斜率（κ = −0.086）**掩盖了两件事**：300 → 1000 档 Λ 是**上升**的；下降只发生在
`1 − R²_unit < 0.05` 的那三档上（40 格里 23 格不稳）。§5 第 5 条讲这意味什么。

## 5. 读的时候不能忘的五件事

1. **A2 调过超参，A3 没有。** A2 的 30 次搜索来自预注册协议（D-51），A3 是官方默认配置、
   一次没调。所以 Λ 为负时，一部分可能是"A2 被调得更好"，不是"链信息有害"。κ 是**同一支臂
   内部沿 n 的斜率**，这个不对等在各档位之间是常数，所以对**斜率**的污染远小于对 Λ 的**水平**
   的污染——但"κ ≈ 0"这句话仍要带上这条限定。
2. **n=300 端的 GNN 方差大。** 最小档只喂 300 行，初始化与批序的影响最重。这批只跑了 seed 0
   （与 A2 对齐），行 bootstrap 抓不到这部分噪声，所以最小档的 Λ 点要读作"一条曲线上的端点"，
   不要单独引用。
3. **分母不稳要显形。** `1 − R²_单元 < 0.05` 的单元格标 `unstable=true`，照样留在表里。
   均聚 Cp 的 A2 在 `all` 档可能已接近饱和，那几格是"分母小"而不是"链臂差"。
4. **这是 A3 的 κ，不是"链信息"的 κ。** 换成 A4（polyBERT 冻结 + ridge）会得到另一个 κ，
   而那个数字更接近 0——原因是线性头容量封顶，不是数据没用（D-69 的决策理由②）。
   引用时务必带臂名。
5. **`κ < 0` 这句话只活在不稳区里，别单独引。** 四种口径都算一遍（同 40 格，只换读法）：

   | 口径 | 交替集 κ | 95% 区间 | 减半比 | 会不会被判成 `H2_refuted` |
   |:--|--:|:--|--:|:--|
   | **预注册**：全部档位、最小档为起点（表里报的就是这个） | **−0.086** | [−0.105, −0.067] | 0.650 | 否 |
   | 去掉最小档（`kappa_leverage.csv`，D-3 ②） | **−0.224** | [−0.241, −0.205] | — | — |
   | 只用**稳定**的两档（300 / 1000） | **+0.398** | — | — | 否 |
   | 起点改取**峰值档**（1000）而非最小档 | −0.086 | [−0.105, −0.067] | **0.380** | **会** |

   三件事要一起说：①**"κ 显著为负"只在包含不稳档时成立**——只用 `R²_unit ≤ 0.95` 的两档，
   斜率是 **正的 +0.398**；②**"减半"是否成立取决于起点取谁**（0.650 vs 0.380，正好跨过 0.5）；
   ③按预注册口径（最小档为起点、含全部档位）`H2` **没有被推翻**，这条结论在四种口径里
   **两种都不满足**，是四个数里最稳的一个。反过来说：**不能只引 κ = −0.086 一句**，
   那会让人以为"数据涨上去 Λ 就掉"，而实测掉的那一段全在分母 < 0.05 的空间里（D-73）。

   **杠杆检查的结果值得单独说**：去掉最小档后 κ 从 −0.086 变成 −0.224，**符号不翻转**，
   区间 [−0.241, −0.205] 仍整段 < 0。这说明"κ 为负"不是最小档一个人撑起来的——
   最小档影响的是**幅度**（它把斜率往 0 拉），不是**符号**。这一点与 ① 的发现并不矛盾：
   ① 说的是"负号只在分母小的空间里有统计意义"，杠杆检查说的是"负号不依赖那一个端点"，
   两句话分别关于**显著性**与**稳健性**。

## 6. 与 Λ 表（`lambda_ci.csv`）的分工

| | `lambda_ci.csv`（D-68） | `kappa.csv`（D-69） |
|:--|:--|:--|
| 问题 | 同一档位上，链臂比单元臂强多少 | 档位变大时，这个差怎么动 |
| 单位 | 一 (task, arm, fold, seed) 一行 | 一 (dataset, fold, tier) 一行 + 一数据集一行汇总 |
| 任务 | 主表 8 任务 + OpenPoly 3 性质（321 行） | 只有 `pb26_scaling_cp`（机制实验） |
| 区间 | 按测试行配对 bootstrap | 同一套，但**跨档位共用下标** |

机制实验在主表里是**代码层面显式排除**的（`lambda_kappa.SCALING_TASK`），不是"恰好配不上对"：
它的 40 个格是 8 个 (数据集, 档位) × 5 折，同一折的**同一批测试行**要在 4 个档位上各出现一次。
混进主表会把"321 对独立的测试点"读成"361 行里有 40 行重复计数"（D-71）。

两张表**不能相互替代**：Λ 高不等于 κ 就小。前者是"缺多少"，后者是"能不能用数据补上"。

```bash
# 3) 守门（合成曲线那 18 条不依赖这 40 条记录，随时可跑）

```

产出三张表：`kappa_cells.csv`（40 格）、`kappa.csv`（一数据集一行，含 `slope_status` 与 `verdict`）、
`kappa_leverage.csv`（去掉最小档的对照，D-3 验收标准②）。
