### 2.2 每条判定的依据长什么样

证据不是"看起来合理"，而是三类可复核的东西，全部写进 `unit_decisions.csv` 的 `evidence` 列：

1. **列名本身**（最硬）：`Tg(℃)`、`Tm(℃)`、`Td(℃)` 自带 ℃；`IWLT(hour)`、`Tensile modulus(GPa)`、`DMPSM(GPa)`、`TSSAB(GPa)`、`P[cm3(STP)cm/(cm2*s*Pa)]` 也都把单位写在表头。
2. **数值量级与文献区间**（旁证）：`Tg` 实测 −123 ~ 495 ℃ 对得上 PDMS（≈ −125 ℃）到 PBI（≈ 430 ℃）；若当 K 读则中位 138 K，低于任何聚合物的 Tg。模量 0.16 ~ 48 GPa 覆盖橡胶增韧到高取向纤维；若混了 MPa 会在 160 ~ 48000 处多出一簇，实测没有。渗透系数换成 Barrer（1 Barrer = 7.5006e−14 同量纲单位）后中位 **2.7 Barrer**、99 分位 **1.3e3 Barrer**、最大 **5.1e4 Barrer**，落在"阻隔型 1e−3 ~ 超透 PTMSP 万级"的文献区间里，说明单位标签与数值自洽。
3. **发布方自己的 `property_log` 列**（交叉验证）：它**逐行等于 `ln(label)`**（Tg 最大绝对残差 5e−10）。若发布方在导出前做过单位变换，这两列不可能这样严丝合缝。

> 【坑十三，写给后来者】`property_log` 是**自然对数**，不是 log10。拿它当 log10 用会得到"看起来差 2.3 倍"的假异常（ln(10) = 2.302585），A-2 验收时就差点踩。任何任务若要用对数目标，**由训练侧现算**，不要复用这一列。

### 2.3 多出来的三列，为什么必须有

分工书的八列里，`n_rows_affected` 这一列被验收标准③用来对账（"调和前后行数差 = `n_rows_affected` 之和"）。但八列无法同时表达两件事：

- 一条**换算**改写了多少行的数值（℃→K 的 8,055 行），它一行都没删；
- 一条**剔除**删掉多少行（本次全为 0）。

若让 `n_rows_affected` 表示"改写"，验收标准③立刻算不平；若表示"删除"，就看不出换算覆盖了多大范围。所以：

- `n_rows_affected` = **删掉的行数**（换算不删行就写 0）→ 验收标准③可以逐任务加总核对；
- `n_values_converted` = **改写数值的行数**（identity 写 0）→ 换算范围可查；
- `task_id` = 分工书那八列里没有任务标识，而这张表覆盖 11 个任务，没有它会串行；
- `decision_kind` = 区分"单位判定""去重""弃列""整任务弃用"，否则同一任务的多行决策无法分辨。

这四处扩展已记入 `docs/DECISIONS.md` D-15，`pytest` 里也有一条测试专门守"行数差 = `n_rows_affected` 之和"。

## 3. 去重：键是 `(task, 规范 SMILES)`，本次删 0 行

| 事实 | 数字 |
|---|---|
| 10 个任务调和前 | 20,660 行 |
| 调和后 | **20,660 行** |
| 其中：SMILES 无法解析 | 0 |
| 其中：标签无法解析（含空值） | 0 |
| 其中：规范 SMILES 重复（任务内） | **0** |
| 这 10 个任务内唯一规范 SMILES | 11,494 |
| 跨任务共享同一结构的行数 | **9,166** |

**为什么删 0 行**：发布方的 CSV 每个任务内部本来就按结构去重过（原始字符串 8,055 行就 8,055 个不同值）。我用 RDKit 规范形式重算了一遍，唯一键数**仍然等于行数**——也就是说原始字符串之间没有"同一分子换个写法"的漏网之鱼。

另外做了一次**哑原子审计**：PolyBench 的 SMILES 是重复单元写法（两端带 `*`）。若某些行把两端写成 `[*:1]`/`[*:2]`，规范形式就会因编号顺序不同而分裂，去重会漏。实测：**10 个任务里含 `[*:n]` 的行数为 0**，且"抹掉哑原子编号后再规范化"得到同样的唯一键数（差 0）——所以按规范 SMILES 去重是稳的。

**为什么跨任务不删**：9,166 行（占 44%）在别的任务里也出现过，那是**同一个结构被测了不同性质**（Tg 和 Tm 都测过），删掉就是丢合法样本。这条已写进 `docs/DECISIONS.md` D-14，也写进了每个任务的 `dedupe` 决策行。
