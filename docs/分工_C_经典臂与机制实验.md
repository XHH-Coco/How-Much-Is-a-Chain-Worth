## 0. 先用大白话讲：你这份差事是干什么的

### 你要干的活，是"把所有不用大电的仪器全开一遍，并且汇总成一张总表"

四个人合写一篇实验报告（写报告本身由仓库所有者负责，不在四个人的分工里）：

- **A** 把样品配好、编号贴好、天平校准，把记录本签好字；
- **B** 开着两台最耗电的仪器（图神经网络、语言模型），只在夜里开；
- **你** 手上是**数量最多的那些仪器**：便宜、不耗电、但要做上千次。而且只有你能把它们整理成一张表；
- **D** 拿你这张表算结论、画图，并审你交出去的记录。

先把"臂"说清楚：**同一批样品、同一套划分、同一批种子，只换一个变量**：

| 臂 | 换的是什么 | 大白话 | 谁跑 |
|:--|:--|:--|:--|
| **A1 地板** | 什么都不学 | 先量一下"瞎猜"有多差。忘了这步，后面所有提升都没有参照 | **你** |
| **A2 经典** | 只给重复单元的描述符 | 标准秤：RDKit 描述符 + XGBoost / 随机森林 | **你** |
| **A3 图** | 只给图结构和消息传递 | 更贵的秤，必须 GPU | B |
| **A4 语言模型** | 只给预训练嵌入 | 别人校准过的秤 | B |
| **A5 链信息（我们的方法）** | 在 A2 的输入里塞进链的自由度 | 给标准秤加一个"链长"刻度 | **你**（在 A2 上注入） |

**A5 是全篇最容易被做歪的一项**：它的定义是"**改输入，不改模型**"。如果你在 A5 里顺手把 XGBoost 换成了更好的模型，那 A5 相比 A2 的增益就分不清是"信息"带来的还是"模型"带来的——而 proposal 的 H3 就是"信息 vs 架构"这个对比。**A5 越界，H3 就作废。**

### 你还负责三批"诊断实验"和一张总表

| 你要跑/要做的 | 给谁用 | 规模 | 卡 |
|:--|:--|:--|:--|
| 数据量扫描（scaling） | D 算 κ（H2 的判据） | 5 档 × 5 折 × 2 性质 × 2 臂 = **100 fits** | CPU |
| OpenPoly 经典臂 | D 求 H4 的交叉点 | 3 性质 × 5 档 × 5 折 × 3 种子 = **225 fits** | CPU |
| 架构迁移 | §5 的架构排序 | 1 性质 × 2 臂 × 5 折 × 3 种子 = **30 runs**（原记 60，已由 DECISIONS D-10 定案） | CPU |
| 主表汇总 | 全队与汇报 | 8 任务 × 5 臂 | — |

三批全在 CPU 上，用的是**你自己在 A2 里调好的超参**和 A 已经算好的特征，**只换训练集大小或换数据子集**——不许另起一套模型。

> **这里有一处容易搞混的分工**：这些实验的判据在 D 手上（κ、H4 的交叉点、架构排序），但跑的人是你。所以定死一条——**你专职跑，D 专职判**，接口只有 CSV + 预测文件。代价是你的验收标准里有一条很硬的要求：**交出去的每一 fit 都必须带预测**，否则 D 的区间和过零点都算不出来；好处是你不用等 D 想清楚怎么判，他也不用来问你"这批是怎么跑的"。

### 做完的标志（一句话）

> **D 拿到 `results/aggregate/main_table.csv` 和每一条 run 的预测之后，能一个人把 Λ、κ、H1–H4 全算完，不需要回来问你任何一句"这个格子是哪次跑的"。**

## 2. 任务清单（拿什么 → 怎么做 → 验收标准）

> 每项标了 pH（人时，含 agent 辅助）与是否关键路径。**6 项固定合计 22.0 pH**（其中运行记录审计 4.0 单列，属于全队审计 14 pH 的一份）。

### C-1 · A1 地板 + A2 经典四臂（5.0 pH｜关键）

| 项 | 内容 |
|:--|:--|
| **拿什么** | B-1 的任务级特征矩阵（`feature_manifest.csv` 说明列含义）+ `splits/`（官方 70/30 或 5 折，二者都用官方文件） |
| **怎么做** | 四个学习器：**Dummy（均值）/ kNN / XGBoost / RandomForest**。统一一套超参空间、统一预算 **≤30 trials**，搜索用 Murcko-grouped CV 且**只在 train 内做**；每个配置跑 **3 个模型种子**；预测落盘 |
| **产出** | `configs/arms/{a1_floor,a2_conventional}.yaml`（含搜索空间与预算表）+ 每 run 一份 `results/raw_runs/<run_id>.json` + `results/aggregate/predictions/<run_id>.parquet` |
| **验收标准** | ① run 记录字段齐全（见 `分工_B` §0 那张 JSON 的字段表），缺一项不算完成；② 同 seed 连跑两遍，`r2` 差异 **< 1e-9**（经典模型是确定性的，达不到说明有随机源没固定）；③ 预测行数 = 测试集行数，`row_id` 与 split 文件逐位一致；④ PolyBench26 上把 `RDKit_RF` 与官方基线数对比，同任务差距 **< 2σ**，> 2σ 时先查协议再报数（不许直接当"我们更好/更差"）；⑤ 预算表写进 `docs/`，被问"调了多少次参"能立刻答 |

> **口径待统一**：§7.1 写"150 fits"，§6 写"96 classical + 48 GNN"。150 − 96 = 54 的来源 proposal 没写明（可能是 A1 与 A5 的复跑）。**开工前与 A、D 一起定死一个数**，写进 `configs/experiments/main_table.yaml`，之后文档只许引用这一个数。

### C-2 · A5 链信息注入臂（1.5 pH｜关键，H3 的一半）

这是"我们自己的方法"，也是最容易被做歪的一项。

| 项 | 内容 |
|:--|:--|
| **拿什么** | B-1 的特征矩阵与图对象；Proposal §6 的 A5 定义（重复次数作为显式特征、wPSMILES 权重、多单元序列拼接） |
| **怎么做** | 三条注入**各自可单独开关**，所以实际产出三组：A5a（重复次数）、A5b（wPSMILES 权重）、A5c（多单元拼接）+ A5all（三条全开）。学习器、超参空间、划分、种子**与 A2 完全相同**，唯一差别是输入矩阵 |
| **产出** | `src/chainworth/arms/chain_info.py`、`configs/arms/a5_chain.yaml`、4 组 run 记录 + 打乱对照 |
| **验收标准** | ① **同学习器同超参**：`config_hash` 除输入特征外必须与 A2 一致，用测试断言；② 三组消融齐全，只开一条也要能跑；③ 加一个**打乱对照**（把链特征在训练集内随机置换后重跑）：若打乱后增益没有下降，说明增益来自"多了几列"而不是"链信息"，**这条必须如实报**；④ 与 A3 的增益在同一 split/seed 上可直接相减（H3 需要"谁降得多"） |

> **为什么加打乱对照**：A5 相对 A2 多了几列特征，任何模型都会因为维度增加而略有变化。没有一个对照，你无法回答"这 0.02 是信息还是维度"。这个对照成本极低（一次重跑），但它是 H3 能不能站住的关键——**D 画图 4 时那根柱子必须有它**。

### C-3 · 数据量扫描 + OpenPoly 经典臂（4.0 pH｜CPU｜关键）

**它只做一件事：把"数据量变大，Λ 会不会变小"变成一条能拟合的曲线。**

| 项 | 内容 |
|:--|:--|
| **拿什么** | PolyBench26 官方 **`Datasets/scaling_indices/`** 里主表两个实验的 `seed_42/`（**不是** `scaling_splits/`——那份被官方 gitignore，见 `SOURCES.md` §2.2【更正】）；A 快照到 `splits/polybench26/<task>/seed_42/` 之后你直接读它，别自己去 clone。档位 300 / 1000 / 3000 / 10000（homopolymer MD_5000 只有 300 / 1000）；OpenPoly 三性质（Tg 443 / 介电常数 295 / Tm 168）；你的 A2 超参 |
| **怎么做** | ① **scaling**：5 档 × 5 折 × 2 性质 × 2 臂 = **100 fits**（XGBoost / RF）；② **OpenPoly 经典臂**：3 性质 × 5 个 n 档（30/60/120/240/all）× 5 折 × 3 种子 = **225 fits**。两批都**复用 A2 的 `config_hash`**，只换训练集大小，不许另调超参 |
| **产出** | `results/aggregate/scaling_cpu.csv`、`results/aggregate/openpoly_cpu.csv` + 每 fit 一条 run 记录 + 预测 |
| **验收标准** | ① 断言读的是 A 快照里 `seed_42/fold_NN.npz` 的**字节级 sha256**，并且训练集是按官方前缀规则 `train_pool[:N]` 取的，**不是自己按行数截的前 n 行**（测试卡死）；② 5 档逐档齐全，homopolymer MD_5000 缺 3000 档要写明"这是事实不是失败"；③ OpenPoly 一律 **n ≤ 443**，不许外推；④ 与 A2 的 `config_hash` 除"训练集规模"外逐字段一致（用测试断言，不是肉眼比对）；⑤ 每 fit 都落预测——D 的 κ 区间与 H4 过零点都要用它重采样 |

> **口径警告**：官方 scaling 的"档"是**给定的索引文件**，不是"取前 n 行"。自己截前 n 行会让 κ 变成"随机子采样的效应"，而不是"官方 scaling 的效应"，而这两件事在结论里完全不同。
>
> **和 B 的分工**：同一网格上 GNN 那 225 条是 B 的（`分工_B` 的 B-5），你只跑经典臂这 225 条。**n 档与折索引是同一份**，谁先跑完都别改档位。

### C-4 · 架构迁移实验（5.0 pH｜CPU｜关键）

| 项 | 内容 |
|:--|:--|
| **拿什么** | PolyBench26 官方 `Datasets/task4_architecture_transfer/` 的**三个脚本**：`create_task4_shared_splits.py`（物化留出集，官方只发布工作流）、`summarize_weighted_predictions.py`（OOD 合成，**这才是 OOD 那一栏的正确算法**）、`evaluate_rdkit_ood.py`（官方地板，用来校验你的物化没做错）；外加官方的 `task4_all_model_scores.csv`（已发布的对账基准）与 A2 的经典臂配置。**训练集 canonical 6,478（交替 6,110 + 均聚 368），OOD 36,828（random 18,414 + block 18,414）；目标只有 electron affinity 一个性质** |
| **怎么做** | 分五步，**顺序不能换**：① **物化**——跑 `create_task4_shared_splits.py --polybert-dictionary …`（那个 224 MB 的 pkl 只有 polyBERT 臂需要，经典臂可省），产物落 `generated/shared_splits/`（gitignored）；跑完先核行数：canonical 6,478（交替 6,110 + 均聚 368）、OOD 36,828（random 18,414 + block 18,414），**与官方 README 对不上就停**；② **先复现官方地板**——用 `evaluate_rdkit_ood.py` 跑一遍 RDKit RF，拿它与 `task4_all_model_scores.csv` 的 RDKit RF 行对照（官方：ID 交替 0.148–0.170、均聚 0.37–0.64；OOD ensemble random 0.536 / block 0.581 / combined 0.559）。差一个量级说明物化或合成错了，别往下跑；③ **30 runs**——1 性质 × 2 臂 × 5 折 × 3 种子，ID 评估直接用每折 test 预测（交替 611 / 均聚 37 行）；④ **OOD 走官方三段式**——从 36,828 行 holdout 取全部唯一组分（`psmiles_a` ∪ `psmiles_b`）→ 用该折该臂该种子训好的模型对**每个组分各预测一次**（一个 psmiles 一条，不许重复）→ 交给 `summarize_weighted_predictions.py` 按 `pred_a·f_a + pred_b·f_b` 合成，得 random / block / combined 各一个点值。该脚本会对「组分缺预测」「摩尔分数不合 1」「psmiles 重复」直接抛错，**不要绕开它自己写加权**；⑤ 五折预测向量全部留档（D-09 要用）。有条件再加 GNN 臂（**可选项，+4–7 GPU-h，由 B 代跑，不计入你的 24 pH**） |
| **产出** | `configs/experiments/arch_transfer.yaml`、`results/aggregate/arch_transfer.csv`、30 条 run 记录、**组件级预测** `results/aggregate/arch_component_preds/<run_id>.csv`（两列 `psmiles,prediction`，就是官方脚本要的输入格式）、**OOD 合成结果** `results/aggregate/arch_ood/<run_id>.csv` + `..._metrics.json`、以及**全部 5 折的 OOD 预测向量**（这个必须留，集成要用） |
| **验收标准** | ① **ID 两档 + OOD 两档分别报**，不许把 ID 与 OOD 混在一张"架构排序"里——它们的可比性不同；② **官方地板复现**：RDKit RF 的 OOD combined 与你实测值的差要在报告里写出来，差距 >0.1 就先查物化而不是调模型；③ **组分覆盖完备**：holdout 里每个唯一 `psmiles` 有且只有一条组件预测（写成断言，缺一条就红）；④ 报告**实际排序**（block > random > alternating > homopolymer 是否成立），而不是只报"通过/不通过"；⑤ 若排序不成立，直接写入 §5 的证伪条件，**不许重调超参再试**；⑥ 若加了 GNN 臂，必须与经典臂同 split / 同种子，否则两列不能并排放；⑦ **OOD 那一栏不得给"均值 ± 标准误"，不得对五折 OOD RMSE 做 t 检验**——折固定、不是独立重复 |

> 【口径警告·必读】 官方 README 原话：*The OOD holdout is fixed across folds, so fold metrics are not independent replicates. ... Do not apply a t-test to the five fold-level OOD RMSEs.* **正确做法**：保留 5 折的 OOD 预测向量 → 按聚合物取平均 → 从五折集成算出 random / block / combined 各**一个** RMSE/MAE/MSE。ID（交替 / 均聚）才允许按折汇总均值与总体标准差。这条同时约束 `分工_D` 的置信区间：OOD 那栏给的是集成点值 + 重采样区间，不是"5 个折的均值 ± SE"。做错了不会报错，只会给出一个假显著的结论。
>
> 【口径已定·D-10】 原条目与 Proposal §7.1 写的是"**2 性质** × 2 臂 × 5 折 × 3 种子 = **60 runs**"。官方 task4 **只做 electron affinity 一个性质**，60 按官方结构算不出来，正确的是 **30 runs**——Proposal 中英已同步改。**5.0 pH 不降**：少掉的 30 次拟合并未让工作变少，因为原计划漏了一整条管线——OOD 那 36,828 行不是直接预测，而是"逐组分预测 + 按摩尔分数加权合成"（官方 `summarize_weighted_predictions.py`，公式 `pred_a·f_a + pred_b·f_b`）。这条管线要额外生成未见组分的特征、按 30 个 run 各算一遍、再合成，恰好是 2 pH 量级的活。**结案记录见 `docs/DECISIONS.md` D-10。**
>
> 【许可】 这个任务的训练源是 polyVERSE（EA），属 **GTRC General Public Use License**，不是主表那个 CC BY 4.0。结果表须随附 GTRC 全文、免费分发、不得商用，且**不能把 GTRC 的条款套到 PolyBench 的任务头上**。投稿或公开仓库时这一栏要单独标许可。

## 7. 红线与常见坑

**红线（做了等于重做）**

1. **自己切数据**：评估必须读 `splits/` 里的官方索引。`train_test_split` 出现在评估路径上就是红线（调参可以用，但必须在 train 内部）。
2. **A5 换模型**：A5 的唯一定义是"同学习器、不同输入"。换了学习器，H3 直接从"信息 vs 架构"塌成"信息 vs 我喜欢的模型"。
3. **用测试集调参**：超参搜索只能在 train 内做 Murcko-grouped CV，一次都不许碰 test。
4. **run 记录手写**：记录只能由训练脚本落盘，手改等于伪造。
5. **机制实验另起超参**：为了"让曲线好看"换个模型或调个学习率，你的 κ 就和主表不是同一个世界了。
6. **主表填 0 充缺格**：缺就留灰并标 `blocked_no_gpu`。

**代码怎么写**：P4 起所有提交的代码按 [`docs/CODE_STYLE.md`](CODE_STYLE.md)——中英双语注释，每个函数写清输入输出、数据来源、配置来源，数字必须有来源。审阅时不看风格，只看"能不能从注释追到数据来源"；追不到的退回重写。

**常见坑**

| 坑 | 现象 | 正确做法 |
|:--|:--|:--|
| kNN 不做标准化 | 结果极差，被解读成"经典方法不行" | 距离度量前标准化，且只在 train 上 fit |
| `X` 里混入全量统计量 | 泄漏，指标好得不像话 | 标准化/编码器只在 train 上 fit |
| scaling 自己按行数截 | 官方档位 ≠ 取前 n 行 | 读官方文件 + 断言哈希 |
| 只存了指标没存预测 | D 无法算 CI，只能报点估计 | 每次运行落 `predictions/<run_id>.parquet` |
| 打乱对照忘了跑 | H3 无法排除"维度增加"的解释 | 一次重跑，写进 `scramble_control.csv` |
| 拿 leaderboard 数直接对比 | 协议不同，被 Q&A 抓住 | 注明版本/模型/划分，差距 > 10% 标 `unexplained` |
| 审计只跑绿不抓错 | 测试永远通过，等于没写 | 故意注入一个错误，看它红不红 |
