## 2. 与分工书写死的列相比，多了两列

分工书 A-2 写的清单列是六列：`task_id, n_rows, sha256, source_url, version, downloaded_at`。实际多出两列，且**没有删改任何一列、没有调整顺序**：

| 多出的列 | 为什么非加不可 |
|---|---|
| `bytes` | 给"文件是不是被截断"一个直接证据。第一次跑的时候 `raw.githubusercontent.com` 就在 20 秒后断连（`curl` 退出码 56），落盘文件只有 32 KB，而 md5/sha256 那两列要等整份文件到齐才能算——`bytes` 是唯一能在"没算完哈希"时就发现异常的数 |
| `n_rows_basis` | `SOURCES.md` §2.2 明确要求"数行数时以文件内条数为准并**在 manifest 注明是哪一种**"。PolyBench26 的下载集里既有 `.jsonl`（数非空行 = 82,990）也有 `.csv`（数数据行 = 7,367）还有 `.npz`（无行数概念），不在清单里写清口径，别人对不出 82,990 是怎么来的 |

取值只有三种：`csv_data_rows`（按 RFC 4180 解析后数数据行，不是数换行）、`jsonl_records`（数非空行）、`not_tabular`（二进制/文本但无行语义，`n_rows` 留空）。`dry_run` 行记为 `dry_run`。

## 5. PolyBench 为什么一个字节都没下回来

### 5.1 现象：不是脚本错，是出口被拦

figshare 的**全部**路径从这台机器都返回 `403`，而且响应头写明了是谁拒绝的：

```text
$ curl -sD - -o /dev/null https://api.figshare.com/v2/articles/30917717
HTTP/1.1 200 Connection Established          ← 代理隧道建立成功（网络本身是通的）
HTTP/1.1 403 Forbidden
Server: awselb/2.0                            ← 拒绝方是 figshare 自己的负载均衡
Content-Length: 118
```

已经排除的可能：

| 试过 | 结果 |
|---|---|
| `https://figshare.com/`、`https://api.figshare.com/v2/articles`、`https://ndownloader.figshare.com/files/…` | 全 `403` |
| 走系统代理 / 不走代理（`--noproxy '*'`） | 全 `403`，响应头同为 `awselb/2.0` |
| IPv4 / IPv6、`http://`、伪装 `User-Agent` 与 `Referer` | 全 `403` |
| `doi.org` 解析到存档页 | `302` 成功，落到 `figshare.com/…/30917717`，随后仍是 `403` |

**同一时刻，用另一条网络路径（不是本机出口）读同一个 API 是通的**：能完整列出 39 个文件、每个文件的 `id` / `name` / `size` / `supplied_md5`，`version: 2`、`license: CC BY 4.0`、`download_disabled: false`。这说明存档本身没问题、也没有被下架，**纯粹是本机出口被 figshare 拦了**。

> 那条通的路能不能直接拿来下文件？**不能。** 它是"取页面文本再交给模型读"的通道，返回的是被转述过的文本，不是原始字节；而我们要的是 39 个 CSV 的**逐字节原文**（md5 必须和发布方公布的 `supplied_md5` 对上）。拿转述文本重建 CSV，等于自己造数据——这正是 A-3 红线「不许猜」拦的东西。所以它只能用来**核对文件清单与 md5**，不能用来取数据。

### 5.2 平台那条路也不通（这条是这次新查清的）

`SOURCES.md` §2.1 留的最后一条「待确认」是"平台的批量获取方式：导出按钮、API，还是只能逐个点"。查完了——**平台没有对外的批量导出，也没有给已标注数据的接口**：

| 端点 | 实测 | 说明 |
|---|---|---|
| `GET /api/data-counts` | `200`，39 条 / 合计 42,169 | 只能数数，不含数据 |
| `GET /api/dataset/test-download?file_name=<名>.csv` | `200`，返回**两列** `polymer_name,SMILES` | 这是"测试集、只给 SMILES、标签不给"的下载口（前端按钮文案就是 *Download Test Set (SMILES only)*）。拿它当完整数据用，等于把 39 个任务的标签扔了 |
| `GET /api/polymers-data` | `200`，分页 JSON，每页 10 条 | 平台自己的展示库，**不是**那 39 个官方 CSV；用它顶替会让 sha256 对不上官方存档 |
| `/api/dataset/download`、`/api/datasets`、`/data/SMILES/<名>.csv` | `404` 或返回前端 `index.html` | 没有未登录的整份下载通道 |

**结论**：PolyBench 只有两条正规入口——figshare 存档（本机 403）或平台登录后手动下载（账号是仓库所有者注册的，按规定不入库，我这边没有凭据）。**脚本不会为了"跑通"去用平台的展示库冒充官方 CSV**：那样 sha256 与发布方对不上，A-3 之后每一个数都会带着一个查不出来的来源。

### 5.3 三条出路（按优先级，选一条即可）

1. **换网络重跑**（最省事）：在能访问 figshare 的机器/网络下执行
   `python scripts/00_download.py --source polybench`，它会自己枚举 39 个文件、逐份校验 `supplied_md5`、写清单、跑完就地把 §4 第 3 条断言也过一遍。
2. **用平台手动下**：登录 <http://202.98.16.11> 逐个下 39 个 CSV，文件名照抄不动，放进 `data/raw/polybench/`，再跑 `--verify-only --source polybench` 补清单（该命令只读盘不联网）。
3. **找人代下**：让对方下同一版本（`v2`）的 39 个 CSV，把每份的 `md5` 抄回来核对——存档页对每个文件都公布了 `supplied_md5`，抄回来能对上的才算数。
