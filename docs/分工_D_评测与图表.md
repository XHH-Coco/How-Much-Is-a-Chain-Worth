## 0. 先用大白话讲：你这份差事是干什么的

### 你要干的活，是"记账 + 当裁判 + 画图 + 抽查"

四个人合写一篇实验报告（写报告本身由仓库所有者负责，不在四个人的分工里）：

- **A** 把样品配好、编号贴好、天平校准；
- **B** 开着两台耗电的仪器（A3 图网络、A4 语言模型）；
- **C** 把其余仪器的读数全测完，汇总成一张总表；
- **你** 要做四件事：
  1. **一个数**：换用更贵的仪器之后，"原本解释不了的那部分"里有多少被重新解释了（这个比例叫 **Λ**）；
  2. **一个斜率**：数据量涨 10 倍之后，这个数动没动（这个斜率叫 **κ**）；
  3. **五张图 + 三句话**：把上面两个数变成能进汇报的东西；
  4. **抽查**：A 的划分、B 和 C 的运行记录、以及最终出去的汇总表，都由你签字。

### Λ 到底在算什么：一个比喻

假设一条高分子的玻璃化转变温度（Tg），用"只给重复单元"的模型去猜，R² = 0.60。也就是说，**还有 40% 的方差解释不了**。

现在换成能看见链的模型，R² = 0.70。它从"解释不了的那 40%"里，抢救回了 10 个百分点。

$$\Lambda=\frac{0.70-0.60}{1-0.60}=\frac{0.10}{0.40}=0.25$$

**所以 Λ 的问法是"漏掉的方差里，你捞回来几成"，不是"你比谁准确"。** 好处是它不带单位：Tg 用 °C、模量用 GPa，Λ 都是同一个意思，所以八个任务可以放在同一张图上横着比。

**为什么分母是 1 − R²_unit**：如果重复单元模型已经解释了 95%，那剩下只有 5% 可以捞，此时"捞回一半"和"捞回一成"在绝对精度上都很小。用 1 − R²_unit 做分母，是把"还剩多少可捞"先标准化掉，否则大任务和小任务根本没法比。

> **一句话记住**：Λ = 0 不是"没有区别"，而是"**这道门已经焊死了**"——剩下的方差，任何链描述符都拿不到。

### κ 在算什么：斜率，不是提升

**κ 是 Λ 对 log₁₀n 的斜率。** 数据从 300 涨到 3000（涨 10 倍）时，Λ 变化了多少，就是这个斜率。

- 若 κ 明显为负 → 数据能买来链信息，那我们这个"缺失坐标"的说法就错了；
- 若 κ ≈ 0 → **数据只买到了插值精度，没买到链信息**。这是本 proposal 最锋利的一句话，也是最容易被攻击的一句话。

所以你要做的不是"证明我们对"，而是**给出一个能被打的量**：κ 的 95% 区间里是不是包含 0。

### 你还得当裁判

四个假设各自有证伪条件（§5）。你的活是**照条件宣判**：

| 假设 | 你要算的 | 判死的条件 |
|:--|:--|:--|
| H1 分层排序 | 6 个 PolyBench 任务上 Λ 与 tier 的 Spearman ρ | ρ < 0.5，或出现跨 ≥2 层的反转 |
| H2 数据不能补偿 | κ 的 95% CI | CI 显著 < 0（注意方向：**"不显著小于 0"才是支持 H2**） |
| H3 信息胜架构 | A5 的增益 vs A3 的增益 | 架构那一边降得更多 |
| H4 交叉点由什么决定 | 三个 OpenPoly 性质的 n\* 与该性质标签离散度的关系 | n\* 不跟着离散度走 |

**判死就要写死。** §7.3 第 8 条写得很清楚：假设被证伪就报被证伪，**不许重调参数直到它成立**。这不是道德要求，是这份 proposal 唯一值钱的地方——它预注册了失败长什么样。

### 为什么审计也在你手上

全队审计 14 pH，分法是"**谁的数字依赖它，谁来查**"：

| 审计 | 你查什么 | 为什么是你 |
|:--|:--|:--|
| **入口 5.0** | A 的划分与泄漏（官方索引是否被绕过、全量统计量是否进特征） | 你的 Λ 分母就是 `n` 和 `split_ref`。划分错了，你的数全错 |
| **出口 5.0** | C 的主表与你自己的汇总：指标是否只有一份实现、是否混了划分版本与标签来源、图与表是否同源 | 出口是你自己的产物，只能自查；独立复核由仓库所有者在写汇报时承担（不占组员工时） |
| 运行记录 4.0 | ——不在你手上，归 C | 他跑出 505/778 的 fit，记录主要出自他手 |

> **一句实话**：出口那 5 pH 是"自查"，不是独立审计。写的时候要老实标出来，别把它说成第三方复核。真正的外部检查点是汇报时的 Q&A。

### 做完的标志（一句话）

> **随便挑一个格子，能从图上的一个点，一路点到某一次运行的某一列预测值。**
> 也就是说：Λ 的每个值都带 `(benchmark, task, split 版本, 单位)` 四元组（§2.1 的 R3），缺一项就不许进图。

## 2. 任务清单（拿什么 → 怎么做 → 验收标准）

> **10 项合计 21.5 pH**（含两端口审计 10.0）。
> 顺序按"先算式 → 再判假设 → 再出图 → 最后审计"排，与开工顺序一致。

### D-1 · 指标实现与 Λ 计算器（1.5 pH｜关键）

| 项 | 内容 |
|:--|:--|
| **拿什么** | B/C 的预测文件 + 真实值（从 A 的 `data/interim/harmonised/` 按 `row_id` 取）；`tests/fixtures/tiny/` 合成样例 |
| **怎么做** | ① 自己实现 R² / MAE / RMSE（**不要只信 run 记录里的数**，从预测重算一遍对拍）；② 实现 Λ = (R²_chain − R²_unit)/(1 − R²_unit)，`unit` 臂 = A2 经典（只给重复单元描述符），`chain` 臂 = A3 / A5；③ **不 clip**：Λ 算出负数就报负数（链信息可能反而有害，这是结果） |
| **产出** | `src/chainworth/metrics/regression.py`、`src/chainworth/analysis/lambda_kappa.py` + `tests/test_metrics.py`、`tests/test_lambda.py` |
| **验收标准** | ① 3 个手算样例（含 R²_unit = 0.6 / 0.95 / 负数情形）与实现逐位一致；② 从预测重算的 R² 与 run 记录差 **< 1e-6**（差更多说明有一边错了，先查再报）；③ `R²_unit ≥ 0.95` 时**只输出 ΔR² 并打标记**，不输出 Λ（分母趋 0，Λ 无意义）；④ 分子分母同时为 0（R²_unit = R²_chain = 1）时返回 `NaN` 并记一条 warning，不许崩 |

> **为什么不许 clip**：把负 Λ 截成 0，图上会显得"所有任务都至少没变差"，这是数据操纵。负值恰恰是 H1 的方向性证据之一。

### D-2 · 置信区间与分母稳定性（1.0 pH｜关键）

| 项 | 内容 |
|:--|:--|
| **拿什么** | D-1 的预测 + 种子集合 `{0,1,2}` |
| **怎么做** | ① 对**测试集残差**做 percentile bootstrap（B = 2000），每次重采样都**重算 R² 再代进 Λ 公式**（不要对 Λ 本身做正态近似）；② 三个种子给出 run 间方差；③ 报 Λ 时同时报 ΔR² 及其区间（§4.3 第 1 条） |
| **产出** | `src/chainworth/analysis/ci.py` + 每任务一行 `results/aggregate/lambda_ci.csv`（列：`lambda, lo, hi, delta_r2, lo, hi, n_boot, seed_policy`） |
| **验收标准** | ① 固定 bootstrap 随机种子后，两次运行结果逐位相同；② 报告里 Λ 与 ΔR² 的**符号一致率**（若某个点上两者符号相反，那一格不许写进结论）；③ 区间宽度 > 0.3 的点标 `undecidable`；④ 差异 < 2σ 的不报成"发现"（§6 第 3 条） |

### D-3 · κ 与 H2 判据（1.0 pH｜关键）

| 项 | 内容 |
|:--|:--|
| **拿什么** | C-3 的 `scaling_cpu.csv`（官方 5 档 / 实际 4 档 × 5 折 × 2 性质 × 2 臂） |
| **怎么做** | ① 对每个性质拟合 Λ ~ log₁₀n（OLS；再加一次按折内方差的 WLS 作稳健性检查）；② κ 的 CI 用折 + 种子的聚类 bootstrap；③ **方向别写反**：H2 的支持条件是"κ 的 95% CI **不显著小于 0**" |
| **产出** | `src/chainworth/analysis/kappa.py` + `results/aggregate/kappa.csv`（列：`property, kappa, lo, hi, n_levels, levels_used, r2_fit`） |
| **验收标准** | ① 拟合图带 CI 带（这是图 3 的底稿）；② 做一次**杠杆检查**：去掉 n 最小的一档重拟合，报告 κ 是否翻转；③ 每个 κ 附四元组；④ 若某性质只有 2 档（homopolymer MD_5000 就是 300/1000），**不拟合斜率**，只报两点连线并标 `2 levels, no slope` |

> **两档不能拟合斜率**——两个点永远能连一条直线，但那条线的斜率没有不确定性可言。这条如果不说，图 3 上会多出一条看起来很确定的假线。

### D-4 · H1 排序检验 + 来源异质性审计（2.0 pH｜关键）

| 项 | 内容 |
|:--|:--|
| **拿什么** | 6 个 PolyBench 任务的 Λ（**只在 PolyBench 内**）；PolyBench26 架构任务的单独结果 |
| **怎么做** | ① **不许跨数据集合并排序**（§2.1 的 R1）：tier 标签只有 PolyBench 有，所以 H1 的 ρ 只在这 6 个点上算，2 个/层；② 画散点，标注每个点属于哪一层，报 Spearman ρ 与 6 个点本身（**不许只报 ρ**）；③ 按 label source（experimental / DFT / MD）分层重算排序，报 Kendall τ；④ leave-one-source-out 重算 |
| **产出** | `src/chainworth/analysis/ordering.py`、`.../heterogeneity.py` + `results/aggregate/{h1_ordering,h1_heterogeneity}.csv` + 图 2 |
| **验收标准** | ① ρ 与 6 个点都画出来；② 若 ρ < 0.5 或出现跨 ≥2 层的反转 → **直接写"H1 被证伪"**，不许换一种排序方式再试；③ τ ≥ 0.6 才能说"分层一致"，否则只报分来源结果、不做合并结论；④ 遇到同一物理量不同测法（Tg 的 DSC vs DMA）→ **不换算**，丢任务并记理由（§2.2）；⑤ **架构任务（`arch_transfer`）的 OOD 那栏不许给"均值 ± 标准误"、不许做 t 检验**——官方 OOD 集跨折固定，5 折不是独立重复，只能先做五折集成（5 个预测向量按聚合物平均）再报一个 point estimate + 重采样区间。ID（交替 / 均聚）才可以按折汇总。见 `DECISIONS` D-09，做错了不报错、只给出假显著 |

## 7. 红线与常见坑

**红线（做了等于重做）**

1. **clip Λ 到 [0,1]**：负值是有信息的结果，截断就是篡改。
2. **跨数据集合并排序**：tier 只在 PolyBench 里有，把 PolyBench26 的点混进 ρ 计算就是 R1 违规。
3. **对 Λ 直接做正态近似**：Λ 是比值，分布是偏的，必须在每次重采样里重算 R²。
4. **两个点拟合斜率**：homopolymer MD_5000 只有 2 档，报连线不报斜率。
5. **图硬编码数字**：图必须从 `results/aggregate/` 生成，手改的图迟早和表对不上。
6. **假设证伪后重调**：§7.3 第 8 条，重调等于把预注册作废。
7. **审计只跑绿不抓错**：测试永远通过，等于没写。

**代码怎么写**：P4 起所有提交的代码按 [`docs/CODE_STYLE.md`](CODE_STYLE.md)——中英双语注释，每个函数写清输入输出、数据来源、配置来源，数字必须有来源。审阅时不看风格，只看"能不能从注释追到数据来源"；追不到的退回重写。

**常见坑**

| 坑 | 现象 | 正确做法 |
|:--|:--|:--|
| R²_unit ≈ 0.95 时算 Λ | 分母趋 0，Λ 跳到 0.8 或 −3，图上出现离群点 | 只报 ΔR² + 标记 `denominator_unstable` |
| 只报 Spearman ρ | 6 个点画出来其实是散的，ρ 靠两个极端撑着 | 散点必画，ρ 是注释 |
| 用三点的 Spearman 证明 H4 | 三个点永远算得出一个 ρ | 明确写"描述性"，不做检验 |
| bootstrap 只重采样种子 | 区间过窄，把噪声当信号 | 重采样**测试残差**（n_test 个点），种子方差单独报 |
| 混算不同来源 | experimental 与 MD 的标签噪声差一个量级 | 分层报告 + Kendall τ 审计 |
| 图里缺失格填 0 | 读图的人以为测出来是 0 | 灰色 + `n/a` |
| 沿用别人算好的 R² | 口径不一致，事后对不上 | 从预测重算，差 > 1e-6 就查 |
| 出口审计写成"独立审计" | 答辩时被问"谁审的你" | 老实写"自查 + owner 对照"，别夸大 |
