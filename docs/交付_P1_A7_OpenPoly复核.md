## 0. 一句话

**OpenPoly 那张 CSV 是 741 行、3,985 个标注，Tg 443 / 介电 295 / Tm 168——五个数全部对上；但顺手发现一件更要紧的事：这 741 行里只有 585 个不同的分子，Tg 那 443 行只对应 304 个结构，而且重复登记的同一种聚合物，不同文献给的值互相矛盾。**

用生活化的说法：这是一张**"不同论文给同一种材料测出不同数值"**的汇编表。你要的"分母"确实存在，但它不是"443 种不同的塑料"，而是"443 次测量，覆盖 304 种塑料"。

## 2. 怎么数的

### ① 不读摘要，直接数列

`741 × 32` 的表：4 列是标识（`Name` / `PSMILES` / `PSMILES_2` / `PSMILES_4`），**28 列是性质**。逐列 `notna()` 计数，合计 **3,985**。

同时核过另一种口径：`pd.to_numeric(errors="coerce").notna()`。**28 列全部一模一样**——说明这张表里没有"看起来像数字其实是文字"的单元格，两种数法不会打架。

### ② 三个点名性质单独核

| 列名 | 非空数 | 与分工书 |
|:--|--:|:--|
| `Tg (K)` | **443** | ✅ |
| `Dielectric Constant Total` | **295** | ✅ |
| `Tm (K)` | **168** | ✅ |

顺带发现：三个介电列（`Electronic` / `Ionic` / `Total`）的**非空行完全相同**（都是 295），是同一批样本的三列，不是三份数据。但 `Total` 与 `Electronic` 逐行**没有一行相等**（`Ionic` 处处非零），所以不能拿 `Electronic` 当 `Total` 用。

### ③ 数"结构"的时候，撞上了真正的坑

分工书写的是"741 行 / **741 个不同 PSMILES**"。这句话不成立：

| 层级 | 数量 | 说明 |
|:--|--:|:--|
| 行数 | 741 | |
| `Name` 唯一 | 720 | 21 行与别人同名 |
| `PSMILES` 原始串唯一 | **656** | 85 行是逐字重复的串 |
| RDKit 规范式唯一 | **585** | 再少 71 个：同一个分子被写成不同字面（如多一种括号写法） |

整表 63 组重复、156 行冗余，**同一个结构最多被登记 14 次**。

### ④ 按 A-3 的口径预演一遍去重，才发现分母不是一句话

A-3 的调和流程是：规范化 → 去解析失败 → 去标签缺失 → **按 `(task, 规范 SMILES)` 去重**。把最后一步套到 OpenPoly 上：

| 性质 | 非空行 | 去重后 | 少掉 | 重复组 | 其中标签冲突 |
|:--|--:|--:|--:|--:|--:|
| `Tg (K)` | 443 | **304** | 139 | 57 | **57（全部）** |
| `Dielectric Constant Total` | 295 | **295** | 0 | 0 | 0 |
| `Tm (K)` | 168 | **83** | 85 | 33 | **33（全部）** |

也就是说：**Tg 的"443"里有 139 行是同一个分子被重复登记，且这 57 组没有一组数值相同**（组内最大极差 **320.9 K**）；Tm 更极端，83 个结构撑起 168 行，33 组全部冲突（最大极差 **201.6 K**）。介电干净——295 行 295 个结构，这也是为什么只有介电那一路的划分天然没有结构泄漏。

举个最直观的例子（PET，同一个规范结构）：

- Tg：353.0 / 327.3 / 351.6 / 346.3 / 350.8 K（5 条文献记录）
- Tm：375.4 / 522.3 / 372.8 / 523.4 K（4 条文献记录）

**所以"去重"在这里不是清理重复值，而是在几个互相矛盾的文献值里挑一个。** 那是建模决策，不是数据清理——A 不做这个决定（见 D-26、Q-06）。

### ⑤ 顺带核实了那个"不许用"的文件

分工书验收②要求写明不要用 `final_polymer_property_counts_from_literature.csv`。我把它从上游取回来核了一遍（commit `ccaa669`，849 字节）：

| 列 | counts 文件 | 训练表实测 | 倍数 |
|:--|--:|--:|--:|
| `Tg (K)` | 58,755 | 443 | ×133 |
| `Refractive Index` | 7,878 | 148 | ×53 |
| `Bandgap (eV)` | 11,146 | 111 | ×100 |
| `Dielectric Constant Total` | 295 | 295 | **×1** |

**58,755 是真的**，它是"匹配结构之前的文献记录数"。两个文件唯一一致的就是介电那一列——因为介电的记录本来就全部匹配上了结构。

> 另一个小发现：**真实文件名里 `from` 后面没有下划线**——`final_polymer_property_counts_fromliterature.csv`。Proposal 与分工书都多写了一个下划线（`..._from_literature.csv`），照那个名字去找会找不到文件，然后有人就会自己"估一个数"。这一点已写成常量 + 测试。

### 3.2 28 个性质列的全貌

| 层 | 做什么 | 成本 | 能抓住什么 |

## 6. 没做到 / 故意不做

1. **没有给 OpenPoly 建调和表。** A-3 的范围是 10 个 PolyBench 任务（`role: main` / `reserve`），OpenPoly 三任务是 `boundary`，A-3 交付时已列为"未做到 #2"。A-7 只数数，不替 A-3 补活——真要补，得先定 Q-06。
2. **没有去重。** 443/295/168 里的重复结构原样保留。理由是去重等于在互相矛盾的文献值里挑一个（D-26）；且 A-5 已冻结的 30 份 OpenPoly 划分是按这 443/295/168 行的 `source_row` 建的，单方面改分母会让划分文件与特征错位。
3. **没有改 A-5 的划分，也没有改 A-4 的 `n_labels`。** A-7 的数字与 A-4 冻结值完全一致（443/295/168），所以 `configs/tasks/*.yaml` 与 `SHA256SUMS` **一字节未动**。
4. **没有算"去重后该怎么切分"。** A-5 复现的官方规则不按结构分组，因此按原样使用会有结构跨集（A-5 已记：Tg 15 个、Tm 14 个、介电 0 个）。要做 group-aware 切分就得出新划分，那是 Q-06 定完之后的活，不塞进 1.0 pH 的 A-7。
5. **没有解读"为什么同一个结构有不同 Tg"。** 这可能是不同测量方法、不同分子量、不同结晶度，也可能是汇编时的匹配误差——**没有依据，不猜**。只报冲突的规模。
